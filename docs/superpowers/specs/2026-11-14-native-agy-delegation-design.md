# agy 原生工具委托：权限边界补充设计

日期：2026-11-14。状态：用户已确认本文及继续实施；三模式已实现，当前真实调用与待验收范围见 [验证记录](../../verification.md)。本文替代原设计中“所有通用委托均限于传入文本”的限制。中文润色边界不变。

## 目标与三种模式

agy 是独立 Agent，可以使用自己的 MCP、Skills、hooks、登录态和权限配置；它不继承 Codex/Cursor 的 MCP 配置。桥接层负责传递任务、必要上下文、结果、错误和取消，不把两个 Agent 合成一个权限主体。

| 路径 | 触发 | agy 配置与目录 | 结果 |
| --- | --- | --- | --- |
| 中文润色／纯文本加工 | 中文文档自动触发，或明确文本加工 | 请求私有配置和临时目录；仅 finish，不加载用户扩展 | 候选文本，宿主审核并写回 |
| 联网搜索 | 用户明确指定使用 agy 搜索 | 独立配置和临时目录，首版仅 search_web / finish；原文由宿主按需核验 | 答案、实际查询和来源，宿主核验引用 |
| 原生工具委托 | 用户明确要求 agy 办事 | agy 自己的既有配置；宿主当前项目的实际目录及获准的读写范围 | 任务结果、共享目录内的制品及执行证据 |

原生委托不是中文润色失败后的兜底渠道。三种模式不相互自动升级；普通问答、文本中引用“调用 agy”均不触发原生委托。

## 方案取舍

- 所有调用都使用原生配置：最接近手工启动 agy，但自动润色也会加载全局启动扩展，扩大自动触发的副作用，舍弃。
- 将 agy 的 MCP 配置复制到受限环境：需要迁移插件、凭据和配置依赖，且不等于 agy 原有环境，首版不采用。
- 按模式隔离能力：文本与搜索在独立空间运行，通用委托共享已授权工作目录，推荐。搜索复用独立配置和进程通道，不为它开放完整原生工具。

## 权限及目录

1. 原生委托沿用 agy 现有权限，不增加 `--dangerously-skip-permissions`、自动批准或放宽权限的 settings。用户已有授权足够时，宿主不重复确认。
2. 委托调用 agy 不意味着允许任意操作。宿主必须将用户本次任务的操作范围、禁止项、输出目标传给 agy；删除、发布、提交、外部系统写入等仍须有对应授权。这些任务约束是 Agent 指令，不冒充操作系统级强制隔离。
3. 通用委托默认以宿主当前项目的实际目录作为 cwd，传入当前任务获准读取、写入的目录以及制品目标目录；不复制工作区或改用影子目录。所有路径按真实路径规范化，制品直接写入双方共享的约定位置。用户另有指定时按其授权调整，并绑定会话。无项目的通用任务使用用户明确的产出位置；缺失且必须写文件时先澄清。
4. 同路径不等于同权限：桥接层不能从一个字符串自动获得 Codex/Cursor 的授权。宿主应提供明确的 readRoots / writeRoots / artifactDir。agy 保留自身原有权限，实际可执行范围受两侧授权共同约束；其权限更严格时反馈限制，不自动提权。目录参数和任务指令是授权契约，不能单独宣传为强制文件系统沙箱；原生 Shell、MCP 和启动扩展是否能被同等限制必须专门验证，不把路径校验冒充完整权限隔离。
5. agy 可经自己的 MCP 访问独立外部数据源；可访问范围由其配置、凭据和服务端权限决定，不因 Codex/Cursor 能访问某路径而自动获得同等权限。
6. 原生配置的全局 MCP、插件和 hooks 可能在第一轮模型调用前启动；启用原生委托即接受这套已配置扩展的正常启动行为。桥接层不能承诺“只读任务一定没有启动副作用”。不编辑、复制或临时改写用户现有全局配置。
7. 通用委托通过 ACP 接收 `session/request_permission`，经 MCP elicitation 在 Codex/Cursor 会话内向用户确认。只回传本次允许或拒绝，不生成永久允许规则，不要求用户切到 agy CLI。宿主不支持表单、用户拒绝/取消、预算耗尽时不批准，并返回待授权或取消状态。模型输出和后续工具参数不能冒充用户点击确认。确认信息包含实际工具、目标路径/命令及影响；过大或无法完整展示的请求默认拒绝。
8. 用户等待计入该任务总预算；界面必须说明到期失效，迟到的批准不执行。授权严格绑定当前请求、session、toolCallId及原始操作内容，不能复用于后续操作。宿主断开连接取消待批请求，并回收本次进程。

## 接口与会话建议

保持现有 `agy_delegate` 的文本契约和默认行为兼容，新增 `agy_run_task` 原生委托工具，避免用一个隐含开关改变既有调用的权限。

`agy_run_task` 初始请求至少包含：requestId、宿主/任务标识、明确委托标记、任务、必要上下文、共享工作目录及 readRoots / writeRoots / artifactDir、任务授权范围、providerRequirement。授权字段记录宿主对用户意图的判断，不能被描述为已验证的人类签名。`agy_health` 分别报告文本路径和原生路径的可用状态。

新增专用 `agy_websearch` 工具及 `agy-websearch` Skill，与 `agy-polish` 对齐；支持宿主技能入口和自然语言显式分流，完整名称按宿主实际命名空间验收。

`/agy` 对明确办事请求使用原生路径；`/agy-polish` 始终走文本路径。Codex 保留对应 `$`／技能菜单入口；不声称所有宿主支持裸 `/agy`。

三种模式分别管理不透明 session token；绑定执行模式、工作目录和任务授权范围。使用明确 conversation ID，禁止全局 `--continue`；不能拿文本 token 续接原生任务，也不能在续接中扩大目录或权限。新增或扩大任务需要新的明确授权。

首版建议继续保留两轮上限和无自动重试。原生任务默认总预算120秒、上限300秒，包含启动及清理；与文本加工30/60秒、搜索60秒的预算分开配置。超时是停止等待和回收本地进程，不是撤销已执行操作。

## 结果、错误与失败降级

- `completed`：原生 CLI 结束并返回合格结果，附其报告的操作、相关路径/资源、验证信息及未完成项；宿主仍须核验，不把模型声称成功当作外部操作证明。
- `needs_authorization`：权限确认未完成，明确说明任务没有完整完成；部分副作用可能已发生。
- `failed` / `cancelled`：停止本次委托，不自动重试、不换 requestId、不换调用渠道。
- `sideEffects` 至少区分 `reported` 和 `unknown`。错误、超时、取消或输出缺失时默认 unknown，不能承诺原状或自动回滚。
- provider 为 preferred 时，宿主可继续处理；若任务可能改变文件或外部系统，先核对当前状态再接手，避免重复提交、发送或写入。核对不清则停在该操作，其他独立工作可以继续。
- provider 为 required 时，失败明确报告“agy 委托未完成”，不能以宿主自行执行冒充完成。
- 取消后仅终止本次拥有的本地进程组，不按名称杀进程，不终止用户已运行的 MCP 服务。脱离进程组的后台任务及远端操作可能继续，必须如实报告边界。

## 实施映射与验收

| 模块 | 改动与验收 |
| --- | --- |
| contracts / MCP | agy_run_task / agy_websearch、新结果与授权上下文；拒绝自动触发、模式/token串用、越界续接 |
| 搜索 driver / parser | 独立空间只开放搜索与网页读取；实际 search_web 事件、失败、缺引用、伪造链接、网页提示注入和超时 |
| 原生 ACP driver / parser | 保留 agy 原有 agent、配置和权限；解析JSON-RPC、工具事件、权限请求与取消，不能沿用文本流解析器 |
| delegation core | 有界并发、请求去重、预算、取消；执行类失败不能简单复用“原稿可直接接手”语义 |
| Skills | 两条路径选择；明确委托与授权范围；副作用未知时先核对再接手 |
| tests / live probe | 独立测试配置中的自有 MCP、hook 正对照；权限不足、部分写入后超时、取消、去重不重复写、范围扩大拒绝、同目录产物可见、read-only目录写入拒绝及符号链接越界 |
| Codex / Cursor | 插件加载、实际菜单名、工具调用、授权不足返回、取消和降级；CLI与GUI分别记录 |
| 文档 / 包 | 同步使用说明、接口、兼容矩阵和包内文档；不自动安装、不改全局配置；提交与推送仅按用户明确授权 |

原生路径的验证先使用独立配置中的虚构文件和本地模拟 MCP；通过后才测试用户自己的 agy 环境，只发已授权的无业务副作用任务。中文润色的独立配置验证不等于原生委托已通过验收。

## 搜索能力的实测与接入约束

2026-11-14，本机 agy1.5.8 的内置 `search_web` 已实际执行。官方 SDK 将它标为 Google Search；官方 hooks 文档列出 CLI 同名工具，CLI changelog 也记录该工具及其来源信息。依据：[工具说明](https://antigravity.google/docs/sdk/tools/)、[CLI hooks](https://antigravity.google/docs/hooks/)、[CLI 更新记录](https://antigravity.google/docs/changelog?tab=cli)。不同账号接入方式可能使用不同服务路由，不把此结论扩大为特定 Google Search API 的固定契约。

独立配置、仅 search_web 与 finish 的试验查询 `site:nodejs.org "v22.12.0"`：原生事件记录 search_web ACTIVE→DONE，搜索步骤约2.46秒，总耗时16.4秒；返回2024-12-03及 [Node.js 官方发布页](https://nodejs.org/en/blog/release/v22.12.0)，宿主另行打开来源核实一致。它证明当前账号可用，不能证明全面优于其他模型或保证未来时效性。

建议搜索输入为 query、目的、域名偏好、语言、providerRequirement，仅发送查询所需信息；检索数量与查询轮次有上限。输出包括实际 queries、answer、sources（title、url、可获得的发布日期）、retrievedAt、限制及引用对应关系。日期缺失必须留空，抓取日期不能冒充发布日期。

本次 CLI stream-json 的 search_web 事件提供工具名称、查询、状态和耗时，未提供完整搜索正文；最终来源列表来自模型的 structured_output。因此必须区分“实际执行了搜索”和“每条结论已由来源支持”。桥接层核验搜索事件和链接格式；宿主按任务风险打开关键来源核验，不伪称桥接层已验证所有引用。若后续 CLI 提供原始来源证据，再渐进增强校验。

网页正文是不可信资料，不是增加权限的指令。搜索模式不开放本地文件、Shell、MCP或浏览器交互；需要查看原文时只加入公开网页读取，并单独验证权限范围。搜索失败不得以模型记忆伪装联网结果；用户允许替代时宿主可明确说明后自行检索，要求必须由agy搜索时报告未完成。

## 宿主内授权的协议证据与验收

用户新增要求：授权始终在 Codex/Cursor 会话内完成。2026-11-14，`agy acp` 在独立配置、虚构文件实验中发送 `session/request_permission`，含 write_file 目标路径、内容diff以及 allow_once / reject_once 选项。模拟本次允许后才写入测试文件，完成后退出0，约11.35秒。模拟响应只证明ACP链路，不等于宿主GUI已验收。

[Antigravity ACP说明](https://antigravity.google/docs/ide/extensions/acp)明确支持暂停等待用户权限确认；[Cursor MCP文档](https://cursor.com/docs/mcp)标注支持elicitation；Codex本机app-server schema含MCP elicitation请求，官方也提供[elicitation接入说明](https://developers.openai.com/plugins/build/mcp-server)。必须分别测试四种宿主的允许、拒绝、取消、断连与超时；不支持的客户端明确降级，不能静默改为终端确认或模型自行批准。
